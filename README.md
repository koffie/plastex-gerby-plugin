# plastex-gerby

A [plasTeX](https://github.com/plastex/plastex) plugin that provides the
[Gerby](https://gerby-project.github.io/) renderer as a standalone, pip-installable
package compatible with upstream plasTeX >= 3.1.

## What Gerby does

[plasTeX](https://github.com/plastex/plastex) (LaTeX to HTML converter)
provides the document parsing and rendering infrastructure that this plugin
builds on.

Gerby is a tag-based publishing system for large, collaboratively maintained
mathematical documents such as the
[Stacks Project](https://stacks.math.columbia.edu/).  The key idea is a
*tag system*: every theorem, lemma, definition, and proof is assigned a short
stable identifier (a "tag") that never changes even as the surrounding text is
reorganised.  Tags let external documents and websites link to a specific
result without the link breaking when the document is restructured.

This plugin generates the tagged HTML fragments that the Gerby web application
then serves.  Concretely, the renderer converts a LaTeX document into a
collection of small HTML files, one per tagged environment:

- Each theorem, lemma, definition, etc. that carries a tag is rendered into
  its own file (e.g. `theorem-1.1-0ABC-thm:foo.tag`).
- Each proof is rendered into a `<tag>-<n>.proof` file.
- Slogans, historical remarks, and cross-references each get their own file.

The Gerby renderer was originally developed as part of the
[gerby-project/plastex](https://github.com/gerby-project/plastex) fork of plasTeX.
This plugin extracts the renderer so it can be used with the maintained upstream
plasTeX without maintaining a fork.

## Installation

```bash
pip install plastex-gerby
```

## Usage

Activate the plugin by passing `--plugins` and `--renderer` to `plastex`:

```bash
plastex --plugins plastex_gerby --renderer Gerby --tags tags book.tex
```

Or set them in a `plastex.cfg` file:

```ini
[general]
renderer = Gerby
plugins = plastex_gerby

[gerby]
tags = tags
```

## Difference from gerby-project/plastex

### `\usepackage{amsthm}` is required

The gerby-project/plastex fork embeds `\newtheorem` and `\proof` as built-in
LaTeX commands, so no package import is needed:

```latex
% gerby-project/plastex (built-in, no package needed)
\newtheorem{theorem}{Theorem}[section]
\begin{proof} ... \end{proof}
```

This plugin targets upstream plasTeX, where these are provided by the `amsthm`
package. You must load it explicitly:

```latex
% upstream plasTeX + this plugin
\usepackage{amsthm}
\newtheorem{theorem}{Theorem}[section]
\begin{proof} ... \end{proof}
```

The rendered HTML output is otherwise identical, except for a minor whitespace
difference in math subscripts (`p_n` vs `p_ n`) which reflects a bugfix present
in upstream plasTeX but not in the gerby-project fork.

## Configuration options

| Option | CLI flag | Default | Description |
|--------|----------|---------|-------------|
| `tags` | `--tags` | `tags` | Path to the tags file |
| `tikz-compiler` | `--tikz-compiler` | `pdflatex` | LaTeX compiler for TikZ pictures |
| `tikz-converter` | `--tikz-converter` | `pdf2svg` | PDF to SVG converter for TikZ |
| `tikz-template` | `--tikz-template` | _(none)_ | Jinja2 template file for tikz |
| `tikz-cd-template` | `--tikz-cd-template` | _(none)_ | Jinja2 template file for tikz-cd |

## Development

```bash
python -m venv .venv
.venv/bin/pip install -e ".[dev]"
.venv/bin/pytest
```

### Regenerating benchmarks

Functional tests compare plugin output against benchmarks generated by the
original gerby-project/plastex renderer. To regenerate them, install the
gerby-project/plastex fork in a separate venv and run:

```bash
pip install git+https://github.com/gerby-project/plastex -t .venv-gerby/lib/...
# or: python -m venv .venv-gerby && .venv-gerby/bin/pip install <path-to-gerby-plastex>
.venv-gerby/bin/python benchmarks/generate_benchmarks.py
```

Commit any updated benchmark files after reviewing the diffs.
